# ADR 0019: UI style

## Status

Accepted (2026-11-07), updated at the release of Strata (2026-11-10).

## Context

The WebUI got a new look, Strata: dark, dense, one accent, IBM Plex type, rows
instead of cards, side-by-side columns and an icon rail. It was built on a
long-lived feature branch next to the old look (called classic), behind a
per-user preference, so the two could be compared and regressions caught. The
only user is the owner, so there was no one to protect with a long transition.

Keeping two UIs for good would double the cost of every later UI change, so
classic was deleted before Strata was released. This record describes what is
left: one UI, one theme.

## Decision

- **Strata is the only UI of the WebUI.** There is no `ui_style` setting, no
  `UiStyle` enum, no `_jupiter_ui_style` cookie and no switch on the account
  page. The migration that added the setting was never released and was
  deleted with it, so the migration chain has no trace of it.
- **One theme.** `buildStrataTheme()` (`infra/component/strata-theme.ts`) is
  built from `strata-tokens.ts` and is the WebUI's only MUI theme. Restyling
  goes through theme overrides first, then small styled wrappers.
- **Strata is dark-only.** The WebUI always paints dark, from the first byte,
  so there is no Night Mode setting (the `use_night_mode` column was dropped
  by a migration) and no cookie for it. A light variant needs a design first.
- **Components do not contain hex values.** They use the theme, or the tokens
  module. Components that published pages share with the WebUI, such as the
  section card and the divider, take their line and text colours from the
  theme, so they read on either theme.
- **Fonts are self-hosted** (`@fontsource/ibm-plex-*`), so self-hosted
  instances work offline.
- **The rail has two widths.** The 52px icon rail, or 176px with labels when
  the user turns on `use_expanded_rail`, the one remaining `WebUiSettings`
  field. It can be changed from the account page, and from the toggle on the
  rail itself, which saves it with a fetcher and keeps its own local state so
  the rail answers at once. The labelled width is only offered from the `lg`
  breakpoint up, so it leaves the columns their room.
- **Panels are columns.** The trunk, branch, leaf and leaflet panels (and tool
  pages, where a trunk would be) are fixed to the window side by side, right of
  the rail, following the unit layout of
  [ADR 0020](0020.strata-unit-layout.md). The panels stay where they are in the
  route tree, so no route file changes for it: each asks a
  `StrataColumnsProvider` (in the workspace route) for its place. The panels'
  own markup was made for a full-width page, so a frame squeezes it with a few
  selector overrides instead of every panel growing a variant.
- **Small screens keep one panel at a time**, as the phone layout of ADR 0020,
  with a drawer in place of the rail.
- **Published pages are standalone.** They are served by their own app
  (`src/published`) with the small theme in `infra/component/theme.ts`, and
  they are not part of the WebUI's look. They render a lone leaf panel, outside
  the columns, which keeps its own full-width frame for that. Restyling them
  with Strata is a separate decision.

## Consequences

- One palette, one typography and one component override set to keep in step.
- Published pages and the WebUI look different, and share only the components
  that read their colours from the theme. Moving published pages to Strata
  would delete `theme.ts`, the Inter and Fraunces fonts, the leaf panel's
  standalone frame and the OS night-mode handling.
- There is no escape hatch back to classic, and no light mode.
